# Архитектура

## Принципы

1. **Этапы независимы.** Сбор не зависит от LLM, обработка — от сети источников,
   дайджест — от того и другого. Падение одного этапа не теряет данные.
2. **Сырьё сохраняется первым.** Всё, что собрано, попадает в `raw_items`
   до какой-либо интерпретации. Если модель недоступна, материал ждёт
   следующего запуска.
3. **Идемпотентность.** Повторный запуск не создаёт дубли: уникальный хэш
   сырья, один сигнал на материал, одно совпадение на пару компания+сигнал.
4. **Ничего не выдумывать.** Пустое поле лучше правдоподобной догадки.
   Reviewer специально ищет непроверяемые утверждения.
5. **Только чтение вовне.** Никаких действий от имени пользователя.


## Данные

| Таблица | Что хранит | Ключ идемпотентности |
|---|---|---|
| `raw_items` | исходные материалы | `hash` UNIQUE |
| `signals` | материалы, прошедшие Scout | `raw_item_id` UNIQUE |
| `analyses` | выводы Analyst, включая доработки | `(signal_id, revision)` |
| `reviews` | вердикты Reviewer | — |
| `companies` | профили компаний | `slug` UNIQUE |
| `matches` | связи сигнал × компания | `(company_slug, signal_id)` |
| `runs` | журнал запусков этапов | — |

Все записи идут в транзакции `BEGIN IMMEDIATE` → `COMMIT`/`ROLLBACK`,
режим WAL. Первая версия — SQLite; интерфейс `Database` узкий, поэтому
замена хранилища не затрагивает агентов.

## Агенты

**Scout** — единственная задача: относится ли материал к российскому экспорту
на Филиппины. Перед моделью работает дешёвый предфильтр по ключевым словам
и жёсткие правила для тендеров (отменённые, просроченные и нерелевантные
закупки отсеиваются без вызова LLM). Порог отбора — `SCOUT_MIN_SCORE`.

**Analyst** — отвечает на вопрос «что это означает для нашей работы».
Получает профили компаний из базы, тендерный контекст и разрешённый список
источников. Поля `sources` фильтруются: ссылка, которой не было в материале,
отбрасывается.

**Reviewer** — критик, работает по принципу **fail-closed**. Часть проверок
детерминированная (нет источников, цифра без источника, год в будущем,
смешение регуляторов, путаница РФ/Филиппины, неизвестная компания,
проигнорированное ограничение для иностранцев, дубликат), часть — через модель.

Вердикты: `PASS`, `REVISE`, `REJECT` и служебный `FAILED`.
`FAILED` означает «рецензия не состоялась» и НИКОГДА не равен разрешению:

| Ситуация | Вердикт | Код ошибки | Повтор |
|---|---|---|---|
| модель недоступна | FAILED | `reviewer_unavailable` | да |
| пустой ответ | FAILED | `reviewer_empty_response` | да |
| ответ не разобран как JSON | FAILED | `reviewer_invalid_response` | да |
| неизвестное значение verdict | FAILED | `reviewer_unknown_verdict` | нет |
| исчерпаны доработки | — | `reviewer_max_revisions` | нет |

Последствия для сигнала: `new` (вернётся в следующий запуск, счётчик
`review_attempts` растёт), затем `failed` при исчерпании попыток либо
`needs_review` при исчерпании доработок. Неподтверждённый сигнал
**не создаёт matches и не попадает в содержательные разделы дайджеста** —
только в статистику раздела «Исключено». Число попыток ограничено
`REVIEWER_MAX_REVISIONS`, поэтому дорогого бесконечного цикла нет.

**Opportunity Radar** — детерминированный модуль без LLM. Сопоставляет сигнал
со всеми профилями: точный HS-код, товарная группа HS, категория, ключевые слова
продукции, прямое упоминание компании и косвенная связь через HS-подсказки
категории. Именно косвенный путь позволяет найти возможность там, где сигнал
изначально не был связан с компанией.

## Профили компаний: источник правды

Источник правды — **`brain/companies/*.md`**. База (`companies`) — производная.

Запись профиля идёт в режиме **merge**: пустое входящее поле не затирает
заполненное в базе. Поэтому пустой Markdown-профиль не может стереть
товары, HS-коды и категории, импортированные из каталога ЦПЭ.
Полная перезапись возможна только явным флагом:

```bash
python -m trade_agent.companies.import_companies catalog.csv --overwrite
```

Существующий Markdown-профиль импорт молча не перезаписывает; для этого
нужен отдельный флаг `--overwrite-profiles`.

## Данные, уходящие во внешний LLM API

Во внешний API (в рабочем режиме DeepSeek через Anthropic-совместимый Messages
API) отправляется:

* заголовок и текст материала источника (Telegram-сообщение, тендерное
  объявление, текст веб-страницы, извлечённый текст PDF);
* URL, идентификатор документа, дата публикации, название источника;
* для тендеров — ведомство, дедлайн, бюджет, заметки о допуске;
* профили компаний из `brain/companies` (название, продукция, HS-коды,
  категории, статус, ограничения, регуляторы, следующий шаг);
* предыдущий вывод Analyst и замечания Reviewer при доработке.

Не отправляется: содержимое `.env`, ключи, токены, Telethon-сессия,
файл базы, логи, пути на диске.

Профили моделей задаются по роли. Scout использует `deepseek-v4-flash` с
отключённым рассуждением и лимитом ответа 600 токенов. Analyst использует
`deepseek-v4-pro` с включённым рассуждением и лимитом 2600 токенов. Reviewer
использует `deepseek-v4-pro` с включённым рассуждением и лимитом 1800 токенов.
Ограничение ответа остаётся обязательным, потому что JSON-ответ модели не
должен превращаться в бесконтрольный расход токенов.

Весь текст источников считается **недоверенными данными** и оборачивается
в блок `<<<UNTRUSTED_DATA …>>> … <<<END_UNTRUSTED_DATA>>>` с указанием
источника и идентификатора документа. Системная часть промпта прямо
запрещает исполнять инструкции, найденные внутри этого блока; собственные
маркеры внутри данных нейтрализуются, размер входа ограничен
`LLM_MAX_INPUT_CHARS`. Ответ модели валидируется по типам и допустимым
значениям — свободный текст в базу не попадает. Признаки попытки внедрить
инструкцию отмечаются в причине отбора, чтобы человек это видел.

Новые внешние сервисы не подключаются.

## Коды завершения этапов

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | частичный сбой: источник недоступен, есть отложенные или неподтверждённые элементы. Собранные данные сохранены |
| 2 | критический сбой: этап не выполнен (нет конфигурации, не записался дайджест) |

## Источники

Каждый источник — класс с методом `fetch(days) -> SourceResult`.
Реестр — `trade_agent/sources/__init__.py`, конфигурация — `sources.yml`.
Добавление источника: запись в YAML, при необходимости — новый класс.
Основной конвейер не меняется.

* `tenders` — мост к существующему модулю `trade-agent/tenders/`. Модуль
  не изменён и по-прежнему работает самостоятельно; мост переиспользует его
  сбор, дедупликацию и оценку, а результат кладёт в общую базу.
* `telegram` — read-only. Обёртка `ReadOnlyTelegram` работает по белому
  списку: доступны только `iter_messages`, `get_messages`, `get_entity`,
  `connect`, `disconnect`, `is_connected`, `is_user_authorized`.
  Всё остальное — включая `start`, `sign_in`, `log_out`, отправку,
  вступление в чаты, реакции и сам объект Telethon-клиента — недоступно
  (`__getattribute__` разрешает только белый список). Процесса авторизации
  в системе нет: сессию создаёт человек вне её.
  Режим по умолчанию — чтение выгрузок существующего модуля.
* `web_html` / `web_rss` — официальные ведомства, ассоциации, пресс-релизы, СМИ.
  Вежливый клиент: таймауты, повторы, пауза между запросами, robots.txt.
  Параметр `days` применяется реально: публикация с распознанной датой
  старше окна отбрасывается. Материал без даты по умолчанию сохраняется
  (`undated_policy: keep`); для источников, где дата есть всегда, можно
  поставить `undated_policy: drop`.
  **Все веб-источники выключены**: ни один адаптер не проверялся на живой
  вёрстке. Наличие класса адаптера не делает источник рабочим.
* `fixture` — локальные файлы для офлайн-тестов.

## LLM

`trade_agent/llm/client.py` — провайдеро-независимый слой. Агенты знают только
`LLMClient`. Первый провайдер — Anthropic Messages API. Чтобы добавить другой,
достаточно класса с методом `complete()` и записи в `PROVIDERS`.

Ограничения: максимальный размер запроса, timeout, повторы, лимит вызовов
на запуск, учёт токенов. Ключи только из `.env`, в логи не попадают
(фильтр `redact`).

`LLMUnavailable` — сигнал «оставить материал в очереди», а не «потерять».

## Именование модулей

ТЗ предполагает команды `python -m trade_agent.fetch`. Каталог проекта
называется `trade-agent` (дефис), а дефис в имени пакета Python недопустим.
Поэтому импортируемый код лежит в `trade-agent/trade_agent/`, а команды
запускаются из каталога `trade-agent`. Данные и база знаний остались там,
где их ожидает ТЗ: `trade-agent/brain/`, `trade-agent/digest/`,
`trade-agent/tenders/`.

## Чего в системе намеренно нет

Веб-панели, React, Docker Swarm, Kubernetes, микросервисов, Redis,
PostgreSQL, векторной базы, автономной рассылки и Hermes. Первая версия —
Python + SQLite + API + Telegram.
