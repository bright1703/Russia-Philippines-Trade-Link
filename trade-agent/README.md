# Trade Agent Intelligence

Небольшой автоматизированный аналитический отдел торгового агента.

Система собирает информацию о филиппинском рынке, отбрасывает шум, связывает
события с конкретными российскими компаниями, проверяет собственные выводы и
показывает человеку только то, что требует решения.

**Решение всегда принимает человек.** Система ничего не отправляет третьим
лицам, не подаёт заявки и не регистрирует компании.

## Конвейер

```
источники → сбор → нормализация → Scout → Analyst → Reviewer → база → дайджест → Telegram
```

Этапы независимы. Сбой одного не теряет данные остальных: сырьё сохраняется
до обработки, и если модель недоступна, материал остаётся в очереди.

## Быстрый старт

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt -c constraints.txt      # production
# для разработки и тестов:
# pip install -r requirements-dev.txt -c constraints.txt
cp .env.example .env          # заполнить ANTHROPIC_API_KEY и токен бота

python -m trade_agent.fetch     # собрать сырьё
python -m trade_agent.process   # Scout → Analyst → Reviewer → Radar
python -m trade_agent.digest    # сформировать дайджест
python -m trade_agent.bot       # команды /latest и /health
python -m trade_agent.notify    # отправить последний дайджест в личный чат
python -m trade_agent.run_pipeline  # полный утренний прогон
```

Проверка без сети и без ключей:

```bash
TRADE_AGENT_FIXTURES=tests/fixtures python -m trade_agent.fetch --days 3650
python -m trade_agent.process --mock-llm      # ответы синтетические, это не анализ
python -m trade_agent.digest --days 3650
```

Тесты:

```bash
python -m pytest -q
```

## Структура

```
trade-agent/
  trade_agent/            Python-пакет (импортируемый, отсюда -m команды)
    config.py             настройки и .env
    models.py             сущности конвейера
    db.py                 SQLite: схема, атомарность, идемпотентность
    fetch.py              этап 1 — сбор
    process.py            этап 2 — агенты
    digest.py             этап 3 — дайджест
    bot.py                Telegram-бот доставки
    sources/              адаптеры источников (telegram, tenders, web)
    agents/               Scout, Analyst, Reviewer, таксономия
    llm/                  провайдеро-независимый клиент LLM
    radar/                Opportunity Radar
    companies/            чтение профилей и импорт каталога
    utils/                хэши, повторы, логирование, HTTP
  tenders/                существующий тендерный модуль (работает и отдельно)
  telegram/               необязательные экспорты и локальные credentials
  brain/                  человекочитаемая база знаний (Markdown)
  digest/                 latest.md и архив дайджестов
  deploy/                 systemd unit-файлы и пример crontab
  tests/                  тесты системы (тесты tenders — в tenders/tests)
  data/                   SQLite (в Git не попадает)
  logs/                   логи (в Git не попадают)
  sources.yml             конфигурация источников
  .env.example            шаблон секретов
```

О том, почему пакет называется `trade_agent`, а каталог — `trade-agent`,
см. ARCHITECTURE.md, раздел «Именование модулей».

Для прямого read-only сбора используются `TELEGRAM_API_ID`,
`TELEGRAM_API_HASH` и уже авторизованная `TELEGRAM_SESSION_STRING` или
`TELEGRAM_SESSION`. Каталог `telegram/` нужен только для старого экспортного
режима.

## Что проверено, а что нет

| Проверено локально на фикстурах и моках | НЕ проверялось |
|---|---|
| сбор из `tenders` и Telegram-выгрузок | реальный Anthropic API |
| нормализация, дедупликация, БД | реальный Telegram Bot и Telethon |
| Scout / Analyst / Reviewer на мок-ответах | живая вёрстка сайтов ведомств |
| Opportunity Radar (детерминирован) | systemd на живом сервере |
| дайджест, коды завершения, offset бота | перезапуск процессов в бою |

**Ни один веб-источник не включён.** Наличие класса адаптера не делает
источник рабочим: каждый адаптер нужно проверить на живой странице
отдельно. Для полного прогона по умолчанию используется Telegram. Источник
`tenders` можно добавить после проверки сетевого доступа к его сайтам.

## Ключевые правила безопасности

* Публикация возможна только после вердикта `PASS` рецензента
  (fail-closed). Недоступность модели никогда не даёт разрешение.
* Профили компаний обновляются в режиме merge: пустое поле не затирает
  заполненное. Полная перезапись — только явным флагом.
* Telegram-бот отвечает только владельцу и только в личном чате.
* Telegram-аккаунт работает по белому списку методов чтения; авторизации
  и записи в коде нет.
* Текст источников считается недоверенным: он изолируется в промпте,
  инструкции внутри него исполнять запрещено, ответ модели валидируется.

## Границы системы

Система **не** делает и делать не должна:

* не отправляет письма и сообщения импортёрам и третьим лицам;
* не подаёт заявки на тендеры и не регистрирует компании;
* не публикует ничего в соцсетях;
* не действует от имени Telegram-аккаунта (только чтение);
* не утверждает, что компания допущена к поставкам — это проверяет человек.
