# Настройка мониторинга Telegram

Мониторинг собирает публикации 10 публичных Telegram-каналов (список —
`RUBRIC.md`) и раз в прогон формирует дайджест значимых для торгового
агента Приморского края событий. Полная логика фильтрации/оценки — в
`RUBRIC.md`, порядок обработки — в `PROCESS.md`.

## Про MCP

В задании упоминался `septagram/telegram-mcp` — такого репозитория не
существует. Из существующих Telegram MCP-серверов ближе всего к
требованию «только чтение» — `sparfenyuk/mcp-telegram`. Но для
периодического автоматического сбора (а не интерактивного диалога с
LLM) отдельный MCP-сервер не даёт преимуществ: все такие серверы всё
равно оборачивают Telethon и требуют тот же вход (api_id/api_hash +
сессия), а заодно предоставляют лишние возможности (отправка сообщений,
управление группами), которые здесь не нужны и создают лишний риск.
Поэтому `fetch.py` использует Telethon напрямую и физически не содержит
кода для отправки сообщений, вступления в группы или изменения
аккаунта — только чтение публичных каналов. Если по какой-то причине
нужен именно MCP-сервер (например, чтобы дальше работать с каналами
интерактивно из Claude Code), `sparfenyuk/mcp-telegram` можно подключить
отдельно теми же credentials — обсудите это, если понадобится.

## Шаг 1. Получить API-доступ

1. Зайти на https://my.telegram.org под своим номером телефона.
2. API development tools → создать приложение → получить `api_id` и
   `api_hash`.

Это данные приложения, не пароль, но их всё равно нельзя коммитить в
репозиторий.

## Шаг 2. Получить session string (один раз, только локально)

**Этот шаг нельзя выполнить через Claude / удалённую сессию** — вход в
Telegram требует код, который Telegram присылает лично вам (в
приложение или SMS), и, возможно, пароль двухфакторной аутентификации.
Session string — это фактически пароль от вашего Telegram-аккаунта, не
передавайте её никому, включая вставку в чат с ассистентом.

На своей машине:

```bash
cd trade-agent/telegram
pip install telethon
python generate_session.py
```

Скрипт спросит `api_id`, `api_hash`, номер телефона, код подтверждения
(и пароль 2FA, если он включён) и выведет `TELEGRAM_SESSION_STRING`.

## Шаг 3. Сохранить секреты

Вариант A — локальный запуск:

```bash
cp trade-agent/telegram/.env.example trade-agent/telegram/.env
# вписать TELEGRAM_API_ID, TELEGRAM_API_HASH, TELEGRAM_SESSION_STRING
```

`.env` уже в `.gitignore` — не закоммитится.

Вариант B — запуск по расписанию (GitHub Actions или Routine в Claude
Code): сохранить те же три значения как secrets в настройках репозитория
(Settings → Secrets and variables → Actions), не через `.env`.

## Шаг 4. Первый запуск (сбор)

```bash
pip install telethon python-dotenv
python trade-agent/telegram/fetch.py
```

Первый запуск для каждого канала берёт публикации за последние 7 дней
(дальше — только новые, по `state.json`). Результат — сырые сообщения в
`trade-agent/telegram/.raw/pending.json` (в git не попадает).

## Шаг 5. Построить дайджест

Обработка `pending.json` в `latest.md`/`archive/`/`state.json` требует
суждения (оценка значимости, дедуп, формулировки на русском по формату
из RUBRIC.md) — это делает Claude по инструкции `PROCESS.md`, не
отдельный скрипт. Попросите Claude (в этом репозитории, на текущей
ветке) выполнить шаги из `PROCESS.md` после того как `fetch.py`
отработал.

## Дальше — по расписанию

После проверки качества первого дайджеста шаги 4–5 можно объединить в
регулярный запуск (например, раз в день):

- локально/на сервере — cron, вызывающий `fetch.py`, затем запрос к
  Claude Code на обработку по `PROCESS.md`;
- или Routine в Claude Code Remote, который по расписанию будит эту
  сессию/репозиторий с промптом «выполнить PROCESS.md» (credentials в
  этом случае должны быть доступны как переменные окружения самой
  среды выполнения — уточните у Claude, когда будете готовы это
  включить).

Скажите, когда добавите секреты — тогда включим автоматический прогон.
