# PROCESS — ежедневный тендерный радар

Инструкция для ежедневного запуска модуля `trade-agent/tenders/`.
Telegram-мониторинг (`trade-agent/telegram/`) работает независимо и
не изменяется.

## 1. Порядок ежедневного процесса

1. Собрать сообщения Telegram (существующий модуль).
2. Обработать Telegram-дайджест → `trade-agent/telegram/latest.md` + архив.
3. Проверить филиппинские тендерные источники:
   `cd trade-agent/tenders && python fetch_tenders.py --days 7`
4. Обработать найденные объявления (выполняется внутри шага 3).
5. Обновить `trade-agent/tenders/latest.md` и `archive/YYYY-MM-DD.md`.
6. Удалить временные файлы (`.raw/` очищается автоматически).
7. Создать **локальный** Git-коммит, если есть изменения.
8. `git push` — только по отдельному явному разрешению пользователя.

## 2. Какие источники проверяются

Список ведёт `sources.yml`. Включены в первом этапе:

| id | Источник | Приоритет |
|---|---|---|
| `philgeps` | PhilGEPS (портал госзакупок) | 5 |
| `da_bid_opportunities` | Department of Agriculture | 5 |
| `bfar_bids` | BFAR (рыболовство) | 5 |
| `doe_transparency` | Department of Energy | 4 |
| `nfa_bids` | National Food Authority | 4 |

Выключенные заготовки второго этапа: DTI, BOI, PPA, DPWH, DOTr,
официальные сайты провинций и городов, страницы ведомств в Facebook.

Facebook — только источник **ранних сигналов**. Такие записи помечаются
`unconfirmed` и обязаны быть подтверждены на PhilGEPS, на сайте ведомства
или в официальном PDF. Cookies и авторизованный профиль браузера
не используются.

## 3. Как определяется новый тендер

Для каждого объявления считается канонический идентификатор
(`normalize.canonical_id`) по приоритету:

1. официальный номер закупки (ITB / RFQ / IAEB и т. п.);
2. номер PhilGEPS;
3. `source_id + agency + title + closing_date`;
4. канонический URL.

Если такого идентификатора нет в базе — объявление считается новым,
в историю пишется событие `new`.

## 4. Как обрабатывается дубликат

Дубли ищутся по: номеру закупки, номеру PhilGEPS, паре «агентство + название»,
паре «название + дата закрытия», совпадению ссылок на документы и нечёткому
совпадению названий (≥ 0.90) при близких датах (± 3 дня).

Записи объединяются в одну: сохраняется источник с наибольшим приоритетом,
к нему добавляются ссылки остальных источников и все найденные документы.
Пустые поля дозаполняются из дублей. Статусы «отменено» и «присуждено»
перекрывают «открыто». В дайджесте такая закупка показывается один раз,
со списком всех источников.

## 5. Как оценивается релевантность

`match.py` сравнивает объявление с профилями из `profiles.yml`.
Вес зависит от поля: заголовок 2.0, категория 1.5, описание 1.0,
агентство 0.7, регион 0.3; «сильные» ключевые слова получают +1.5.
Исключающее слово снимает профиль целиком.

Шкала:

| Оценка | Значение |
|---|---|
| 5 | прямая и сильная возможность для российского/приморского поставщика |
| 4 | высокая релевантность, требуется проверка условий |
| 3 | потенциально интересно, но есть существенные ограничения |
| 2 | слабая связь |
| 1 | почти не подходит |
| 0 | нерелевантно |

Понижение оценки: тендер только для филиппинских поставщиков (потолок 2),
контракт уже присуждён (потолок 1), дедлайн прошёл (потолок 1),
закупка отменена (0). Причины оценки всегда пишутся в `match_reasons`.

В дайджест попадают объявления с оценкой ≥ 3.

## 6. Как проверяется дедлайн

`closing_date` берётся из поля источника, иначе из текста по меткам
(«Deadline of Submission of Bids», «Closing Date», «on or before» и др.),
иначе из PDF-приложения.

| `deadline_status` | Условие |
|---|---|
| `urgent` | менее 3 дней |
| `closing_soon` | 3–7 дней |
| `open` | более 7 дней |
| `closed` | дедлайн прошёл |
| `deadline_unknown` | дата не найдена |

`priority_score = оценка × 10 + бонус срочности + приоритет источника`.
Срочные и высоко оценённые объявления идут в начало дайджеста.

## 7. Ограничения для иностранных компаний

Система **никогда** не утверждает, что российская компания вправе участвовать.
`match.assess_eligibility` ищет в тексте признаки:

* требование регистрации на PhilGEPS / Platinum Membership;
* упоминание филиппинского TIN и регистрации в BIR;
* требование местных разрешений (SEC/DTI, mayor's permit) → нужно юрлицо или партнёр;
* прямое ограничение «только филиппинские поставщики» (в т. ч. правило 75 %);
* упоминание иностранных участников / международного конкурса;
* необходимость СП или локального дистрибьютора;
* нотариальные и языковые требования.

Последней строкой всегда добавляется:
`Eligibility: requires verification with the procuring entity`.

В каждом блоке дайджеста печатается фиксированный список «Что проверить».

## 8. Какие файлы обновляются

* `trade-agent/tenders/latest.md` — текущий дайджест (перезаписывается);
* `trade-agent/tenders/archive/YYYY-MM-DD.md` — копия за день
  (создаётся один раз в день, прошлые дни не трогаем);
* `trade-agent/tenders/tenders.db` — база с историей (в Git не попадает);
* `trade-agent/tenders/.raw/` — временные PDF (очищается, в Git не попадает).

Режим `--dry-run` не трогает ни архив, ни базу, ни `latest.md`.

## 9. Какие ошибки критические

Некритические (запуск продолжается, ошибка пишется в stderr и в раздел
«Источники, которые не ответили»):

* сайт не ответил, таймаут, 5xx, 429;
* robots.txt запрещает обращение;
* PDF недоступен, повреждён или зашифрован;
* страница изменила вёрстку и селекторы не сработали;
* одна запись не нормализовалась.

Критические (запуск прекращается, код возврата 1):

* нет или битый `sources.yml` / `profiles.yml`;
* не создаётся каталог модуля или база данных;
* недоступен `latest.md` для записи.

Если ошибок 0, но `New notices: 0` несколько дней подряд — это сигнал,
что изменилась вёрстка источника, а не что закупок нет.

## 10. Как очищаются временные данные

`.raw/` очищается в конце каждого запуска (`pdf_extract.cleanup_raw`).
Флаг `--keep-raw` оставляет файлы для локальной отладки — но они всё равно
не коммитятся. Файл `.gitkeep` не удаляется.

## 11. Что модуль не делает

Не отправляет сообщения в Telegram, не подаёт заявки, не регистрирует компании,
не шлёт email, не использует Facebook API и GitHub Actions, не читает `.env`,
cookies и токены, не выполняет `git push` без явного разрешения.
